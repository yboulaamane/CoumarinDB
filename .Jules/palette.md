## 2024-05-10 - Refactoring Nested Links in Buttons for Accessibility
**Learning:** Nesting interactive elements, specifically `<a>` tags inside `<button>` elements, creates invalid HTML and breaks keyboard accessibility and screen reader functionality. This is a common pattern when developers want the visual styling of a button but the navigation behavior of a link.
**Action:** Always replace the nested `<button><a>...</a></button>` anti-pattern with a single semantic `<a>` tag. Apply appropriate CSS classes to the `<a>` tag (e.g., `display: inline-block`) to achieve the visual button styling. To ensure the component remains fully accessible and maintains interactive feedback, always define `:hover` and `:focus-visible` pseudo-classes. When using icon-only buttons or ambiguous text, add an appropriate `aria-label`.
