## 2024-04-15 - Fixed Inaccessible Nested Button Links
**Learning:** Found a common anti-pattern where a semantic `<a>` link (used for downloading a file via an external URL) was nested inside a `<button>` tag to achieve button-like styling. This creates invalid HTML, completely breaks keyboard accessibility (as both elements might receive focus but with competing behavior), and confuses screen readers.
**Action:** When styled links are needed (like download buttons), always use semantic `<a>` tags with CSS classes (like `display: inline-block`) to achieve the visual button look. Ensure `:hover` and `:focus-visible` pseudo-classes are defined to restore the visual interactive feedback native buttons provide. Also, prefer relative paths with the HTML5 `download` attribute rather than linking directly to the absolute GitHub file URL, to avoid forcing users onto a new page.
