## 2024-04-03 - Nested Interactive Elements Break Accessibility
**Learning:** In standard HTML, nesting interactive elements (like placing an `<a>` inside a `<button>`) results in invalid HTML and breaks keyboard accessibility and screen reader support. Native `<button>` elements are for actions, while `<a>` elements are for navigation or resource downloading.
**Action:** When styling a download link or navigation item to look like a button, always use a semantic `<a>` tag and apply CSS classes to mimic button appearance (including `:hover` and `:focus-visible` states), rather than wrapping the `<a>` in a `<button>` tag. Also, use relative paths with the HTML5 `download` attribute for file downloads to ensure they don't incorrectly navigate to repository UI pages in a new tab.
